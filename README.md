## 项目介绍

补货订阅为客户提供一个集中管理商品到货提醒的入口。客户选择关注的商品、库存门槛和通知方式，达到条件后自动接收提醒；商品隐藏或删除时也会收到独立的下架通知。

商家可以根据订阅人数和门槛分布安排补货，控制邮件与短信的发送频率，配置企业微信、钉钉及通用 Webhook 群通知，也可以针对多个商品预览后统一发送补货通知。

插件独立安装，复用 V10 的账户、权限、菜单、定时任务、通知模板和发送接口。当前版本为 **0.1.0 测试版**。

## 功能明细

| 分类 | 主要功能 |
| --- | --- |
| 客户订阅 | 集中入口、多商品选择、个人库存门槛、一次提醒与持续订阅 |
| 自动库存判断 | 商品总库存、补货轮次、首次基线、售罄后再次补货 |
| 通知渠道 | 邮件、短信、个人 Webhook，各渠道由商家独立开放 |
| 商家群推送 | 企业微信、钉钉、通用 JSON；商品范围与群库存门槛 |
| 多商品合并 | 按客户、渠道、接收地址合并；人工群发按批次合并 |
| 下架通知 | 商品或上级分类隐藏、商品删除时通知有效订阅客户 |
| 模板与邮件 | 原生模板编辑、系统 Logo、紧凑清单、完整通知详情 |
| 发送控制 | 邮件／短信分别限速、短信每日额度、冷却及通知有效期 |
| 管理与统计 | 分类商品列表、订阅需求、人工群发预览、个人地址管理 |
| 记录与维护 | 通知明细、待处理记录、筛选搜索、操作日志、人工核对 |

### 客户订阅与购买入口

- 购物车商品列表公共区域提供唯一入口，售罄和空列表时也可进入；会员中心提供独立管理菜单。
- 游客先完成系统登录，再自动返回补货订阅页或本次通知详情。
- 按分类搜索和多选商品，批量设置通知渠道、库存门槛及提醒模式；已有订阅可逐项修改或退订。
- 每位客户对同一商品保留一份订阅，邮箱和手机号使用账户已绑定的资料。
- 门槛使用严格“大于”：设置为 **3**，表示至少有 **4** 件库存时提醒。建议设置为 3 及以上，减少临时库存归还造成的提醒。
- 提供“提醒一次”和“持续订阅”。持续订阅在再次确认售罄并补货后进入下一轮；同一轮库存波动不会重复提醒。

### 库存观察与补货轮次

- 使用商品总库存，支持 `0 → 1 → 5` 逐步补货时按各客户门槛触发。
- 首次开放、重新开放及插件重新启用建立库存基线，不推送已有库存。
- 商品编辑、订单与服务库存相关钩子配合系统分钟任务检查，按商品批量读取，不逐个客户重复查询库存。
- 使用 V10 已有上游库存同步结果，不增加独立上游轮询；无法可靠确认库存时等待后续复核。
- 调度短暂延迟后保留原补货轮次、待发通知和有效期，恢复时继续核对当前条件。

### 邮件、短信与个人 Webhook

- 后台独立开放邮件、短信和个人 Webhook；未开放短信时，客户绑定手机号也不能选择短信订阅。
- 邮件、短信复用 V10 原生接口、通知动作、模板和发送日志。
- 个人 Webhook 内置企业微信机器人、钉钉机器人、通用 JSON，可配置可选签名密钥。
- 个人接收地址可以复用到多份订阅；停用草稿可先保存，启用及发送时校验目标地址。
- 保存设置不会发送测试消息，个人和商家地址均提供显式测试按钮。

### 多商品合并与商家群

- 自动通知按客户、渠道和接收地址合并，默认合并窗口为 60 秒；人工群发按本次批次合并。
- 每个渠道只包含客户为该渠道订阅的商品，长 Webhook 消息按平台长度限制拆分。
- 商家群只由后台配置，可独立设置商品范围、库存门槛和接收地址；没有个人订阅也能工作。
- 每个群、每个商品在一轮补货中只提醒一次。群通知不包含客户资料，也不完成个人订阅。

### 商品下架提醒

- 商品隐藏、上级分类隐藏或商品删除后，通知仍有效的订阅客户；历史商品名称继续保留。
- 下架通知与补货通知分别合并、分别使用模板，共用渠道开关、短信额度和发送频率。
- 商品恢复上架时取消尚未发送的旧下架提醒；下架通知不完成一次补货订阅，也不改变补货冷却时间。

### 邮件与通知模板

- 登记单商品补货、多商品补货、单商品下架、多商品下架四套通知动作及邮件／短信模板。
- 后台提供 V10 原生模板编辑、接口关联和参数说明入口；更新保留商家自定义模板。
- 邮件使用系统 Logo、小圆角和紧凑列表，每个商品一行，最多展示 10 个商品；超出部分可进入本次通知查看完整清单。
- 默认短信不包含链接，程序不追加链接；商家可在模板中按需使用购买、订阅管理或通知详情链接参数。
- 支持短信短商品名称和签名长度预留，群发预览显示预计计费条数。

### 发送频率与短信费用

- 邮件和短信分别设置每分钟 1–1000 次提交上限，默认邮件 20 封、短信 10 次，使用连续 60 秒窗口。
- 自动补货、下架、人工群发及明确失败的重试共用对应渠道限额；邮件、短信互不占用。
- 超额通知在原有效期内等待后续调度，不消耗重试次数和短信每日额度。
- 短信支持每人每日额度、全站每日额度、同客户同商品发送间隔；并发发送计入额度预占。
- 预计计费条数依据最终模板内容估算，包含签名预留；实际计费以短信服务商为准。

### 后台商品与订阅管理

- 商品列表沿用系统分类和排序，分类支持全选、取消、半选以及展开收起；商品名称可打开原商品页面。
- 按名称、编号、分类和开放状态筛选；批量开放／关闭前预览客户、订阅和待发通知影响。
- 查看有效订阅人数、门槛分布及最近通知，点击需求人数可进入对应商品的客户订阅。
- 后台客户和商品链接均在新标签页打开；已删除商品保留名称，不提供失效链接。
- 管理员可以查询、停用和恢复个人 Webhook，客户不能绕过后台停用。

### 补货群发、记录与诊断

- 人工群发支持多选商品，客户通知和商家群通知分别选择；只发送有效订阅且达到门槛的商品。
- 发送前预览去重人数、渠道数量、短信预计条数及跳过原因；相关条件变化时要求重新预览。
- 通知记录按商品、客户、渠道、类型、状态、来源及日期等条件筛选，支持搜索及逐商品处理结果追踪。
- 后台提供待处理明细、未通知原因、运行心跳及脱敏接口错误；会员只查看本人通知，不展示后台诊断。
- 明确失败可以在规则范围内重试；结果未知保留人工核对入口，登记结论不会触发重复发送。
- 可选历史记录逻辑归档，保留通知、去重、短信费用和审计事实。

### 页面适配与权限

- 后台复用 V10 页面框架、TDesign 和通用插件组件，按查看、设置、群发、记录、管理及人工核对分别授权。
- 会员页适配标准主题与 CRA1。手机端收起高级筛选，表格内部横向滚动，保留搜索和常用操作。
- 设置及地址编辑发生冲突时保留当前草稿；未保存设置有明确提示。
- 退订、地址变化、关闭渠道和库存下降会在发送前再次复核；通过事务、任务认领与唯一约束避免并发重复。

## 快速安装

1. 从 [GitHub Releases](https://github.com/zbxh/cr-stock-subscribe/releases) 下载 `CrStockSubscribe-0.1.0.zip`。页面自动生成的 Source code 是仓库源码，不是商城安装包。
2. 解压到 V10 的 `public/plugins/addon/`，确认入口为 `cr_stock_subscribe/CrStockSubscribe.php`。该 ZIP 的顶层就是 `cr_stock_subscribe/`。
3. 在后台应用／插件管理中安装并启用“补货订阅”，然后在插件后台开放允许订阅的商品。
4. 配置通知渠道和 V10 原生邮件／短信接口；短信默认关闭，需要关联模板并完成服务商要求的审核。
5. 确认 V10 原有分钟任务及通知队列运行正常，再使用专用商品和本人地址测试通知。

首次开放商品只建立基线，不立即通知当前库存。完整配置、模板参数、Webhook 签名和常见处理方式见 [使用指南](docs/guide.md)。

## 默认设置

| 设置 | 默认值 |
| --- | --- |
| 通知渠道 | 邮件、个人 Webhook 开启；短信关闭 |
| 每人有效订阅／有效期 | 20 个／90 天 |
| 库存门槛 | 超过 3 件，即至少 4 件 |
| 检查间隔／合并窗口 | 60 秒／60 秒 |
| 邮件／短信每分钟提交上限 | 20 封／10 次 |
| 同客户同商品提醒冷却 | 1 小时 |
| 同客户同商品短信间隔 | 24 小时 |
| 每人／全站每日短信预计额度 | 3 条／100 条 |
| 通知有效期 | 30 分钟 |
| Webhook 最大尝试次数 | 3 次，包含首次 |
| 初始开放商品／商家群 | 未配置 |

## 兼容与运行环境

面向智简魔方 V10 业务系统 **10.7 系列**，使用系统原生插件、钩子和通知接口；具体已验证版本、主题及运行条件见 [兼容说明](docs/compatibility.md)。插件以 PHP 7.4 为运行基线，代码保持 PHP 7.4 语法兼容，较新 PHP 的语法检查与 V10 整站运行兼容分别记录。

通知依赖站点既有定时任务、邮件／短信接口及客户接收设置。提醒依据商品总库存，不预留库存，也不代表某个地区、线路或机型一定可购买；接口受理状态不等同于客户最终收到或阅读。

## 开发与测试

运行源码位于 `public/plugins/addon/cr_stock_subscribe/`，无需前端构建或 Composer 安装。`scripts/` 和 `tests/` 是开发验收辅助工具，不会进入商城安装包，也不需要部署到站点。

```bash
python3 scripts/check.py
python3 scripts/package.py --output /path/to/output
```

检查范围和外部 V10 环境验证方式见 [测试说明](docs/testing.md)。
