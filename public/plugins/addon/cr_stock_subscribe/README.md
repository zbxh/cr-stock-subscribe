# 补货订阅 0.1.2

独立 V10 插件，标识 `CrStockSubscribe`。作者 Cr，QQ 793305720，交流群 603107399。

客户按商品总库存和个人门槛订阅补货，可同时选择邮件、短信及个人 Webhook。商家可以独立设置群机器人、查看补货需求，并对多个商品预览和群发补货提醒。

## 安装和首次设置

1. 将安装包解压到站点 `public/plugins/addon/`，确认入口为 `cr_stock_subscribe/CrStockSubscribe.php`。
2. 在 V10 后台插件管理中正常安装并启用“补货订阅”。无需覆盖系统、主题或其他插件。
3. 打开插件后台“商品与订阅”，选择允许订阅的商品。首次开放只记录库存基线，不推送当前库存。
4. 在“插件设置 → 基础设置”中确认功能、客户可用渠道及订阅限制，在“通知规则”中设置检查、合并、冷却和短信额度。两页共用“保存设置”，切换设置子页保留草稿；出现“有未保存的修改”时请保存后再刷新页面。在“通知模板”中打开 V10 原生通知接口和模板管理。短信默认关闭，默认短信模板为本地草稿，须关联正确接口并完成服务商要求的审核。
5. 如需群通知，在“插件设置 → 商家群 Webhook”中新增地址，配置商品范围、门槛和开关。保存不会发送测试；使用“测试”按钮单独验证。“个人 Webhook”子页按客户编号查询和停用脱敏的个人地址。
6. 确认站点原有 V10 定时任务和发送队列正常运行。插件复用每分钟任务和 V10 邮件、短信队列，后台显示最近检查时间。

安装时没有适用商品或群地址，不会自动群发。普通管理员角色不会自动获得新增权限；请按需分配查看、设置、群发、记录及取消/重试权限。

插件后台进入时会读取 V10 当前管理员权限，安装前已登录的管理员也可正常打开。权限读取失败时点击“重新读取权限”；未分配权限会显示明确提示。表单错误显示具体原因，Webhook 保存错误也会显示在当前弹窗内，改正后可直接重新保存。

## 列表查看

后台和会员端列表分别展示门槛、渠道、模式、状态、进度、时间等字段。编号、数量和状态占用紧凑列，商品名、地址和说明使用较宽的内容列。长文本单行省略，悬停可查看完整内容；多商品通知在主表显示商品摘要与总数，打开详情或展开记录可查看完整商品清单及发送尝试，不受邮件最多展示 10 项的限制。

渠道列按当前订阅使用的渠道收紧宽度，操作列保留当前需要的完整按钮；没有待发进度或复核时间时不预留对应空列。窄屏和手机可在表格内部左右滑动查看其他列。库存数量和价格继续遵循后台展示开关，未通知原因仅限后台管理员查看。

手机端“我的订阅”和“通知记录”默认保留搜索、查询和重置，高级筛选通过“展开筛选”打开；折叠不会清除已填条件，按钮显示已填写的高级条件数。桌面端仍直接展示全部筛选。过期提醒不再计入待发进度，列表与状态筛选按实际有效期显示，无需等待下一次定时任务。

## 客户使用

购物车商品列表顶部有唯一“补货订阅”入口，售罄或商品列表为空时仍保留。客户也可以从会员中心菜单进入。游客先完成系统登录，随后自动回到订阅页。

- **我的订阅**：查看、逐项修改、重新订阅和退订；支持商品名称／订阅编号搜索，按状态、渠道、提醒模式及创建日期组合筛选。可在“新增／修改订阅”中多选新商品批量订阅；已有有效订阅请从“我的订阅”打开修改，重复新增会给出提示，避免旧页面意外覆盖。
- **新增订阅**：按分类筛选、搜索和跨页多选商品，然后设置库存门槛、通知渠道和提醒模式。
- **通知记录**：搜索商品名称或事件编号，按通知类型（补货／下架）、发送状态、渠道、自动／人工来源、商品编号及创建日期筛选；展开合并通知查看商品清单和接口处理结果。仅显示本人的通知。
- **个人 Webhook**：维护可复用到多份订阅的个人地址，支持显式测试；商家群地址只在后台配置。选好商品后可以进入“管理个人 Webhook”新增地址，再点“返回订阅设置”继续，已选商品、门槛、渠道和模式会保留；页面刷新前请保存订阅。

门槛使用严格“大于”。默认填写 **3**，表示“库存超过 3 件，即至少 4 件时提醒”。建议设置为 3 及以上，减少资源尚在回收站、库存临时加一造成的提醒。少量有货但低于个人门槛时可以订阅；已经满足门槛时，新增订阅会提示直接购买或提高门槛。

邮箱和手机号取自当前登录账户的绑定资料，并遵循 V10 接收通知设置。后台没有开放的渠道无法选择。退订、更换接收地址或关闭渠道会阻止尚未发送的旧任务。

**提醒一次**：至少一个所选个人渠道返回接口成功后完成订阅，其余已经安排的个人渠道继续按原规则处理；仍有待发渠道时可以停止待发提醒。**持续订阅**：同一轮补货只提醒一次，确认再次售罄并补货后进入下一轮。商家群通知不会完成客户的个人订阅。

通知依据商品总库存，不承诺某个地区、线路或机型可购买，也不预留库存。关闭库存控制的商品不视为库存零；隐藏、删除或库存不可靠的商品停止补货提醒；已确认隐藏或删除时会发送独立的下架通知。上游商品使用 V10 既有同步结果，超出有效期记为未知，不另外请求上游。

## 后台操作

- **商品与订阅**：按 V10 系统分类和商品顺序查看树形列表，支持全部展开、收起和刷新保留折叠位置。按分类（包含下级分类）、开放状态或名称筛选；输入商品编号或 `#编号` 精确查找。勾选分类会选中其下全部商品（含子分类和收起的商品），取消分类勾选会取消对应商品；部分商品已选时分类显示半选，空分类不可勾选。筛选后只选择当前结果，改变筛选会清空旧选择。多选商品后批量开放、关闭，每批最多 200 个。库存异常原因和订阅门槛分布在悬停提示中展示；有查看权限时点击订阅人数进入对应商品的客户订阅。未分类、分类异常商品仍可查看和管理；空分类保留在未筛选列表中。
- **补货群发**：多选商品，分别选择客户通知和商家群通知。预览去重客户数、各渠道数量、短信预计计费条数与跳过原因，然后确认本批发送。只包含客户订阅且达到个人门槛的商品；与自动通知共享去重、冷却和短信限制。
- **通知记录**：查看渠道、商品、每项处理结果、尝试记录和关联 V10 任务编号。仅明确失败且未过期、未达到尝试上限的任务可重试。
- **插件设置**：渠道、展示内容、限额和时效，原生模板编辑入口，商家群及脱敏个人地址管理。后台可停用异常个人地址；客户列表会显示地址已停用，停用时测试不可用。后台不读取个人完整地址或密钥。删除商家群地址时先确认名称、关联商品及待发通知影响；取消不修改配置，确认删除后仍保留历史通知记录。

后台客户订阅中的客户编号、商品名称，以及商品开放设置中的商品名称可点击进入 V10 对应详情。通知记录和详情也提供客户及商品链接；后台页面内所有跳转链接均在新标签页打开，保留当前筛选及操作位置。

分类和商品沿用系统设置的排序，同一排序值按编号稳定排列。分组行支持展开、收起和勾选下属商品，批量设置只提交实际商品编号；设置权限与客户订阅查看权限分别校验。

批量开放／关闭先展示商品清单、将修改／保持原状的数量，以及涉及的有效订阅、去重客户和待发提醒数量，点击确认后才保存。取消不修改商品。关闭会停止相关待发提醒，保留订阅及历史；已经开始发送的请求可能无法撤回。预览后商品状态或影响范围改变时会拒绝旧确认，需要重新预览。首次或重新开放仍只建立库存基线，不补发当前库存。

### 运行状态与未通知原因

后台顶部显示最近自动检查启动时间、最近完整成功时间（悬停查看）、待发送／待合并／冷却等待数量和最长等待时间，每 60 秒只读刷新，也可以点击“刷新状态”。从未运行、检查超过预期间隔、最近检查失败或到期任务等待过久时会给出具体提示；插件暂停时明确显示暂停。有记录查看权限的管理员可以直接进入“查看待发记录”。运行状态依据插件实际心跳和任务数据，不会启动系统定时任务或强行补发。

仅后台“客户订阅”提供“查看未通知原因”，会员页面不展示入口，会员接口也禁止读取诊断信息。详情说明当前是否严格超过个人门槛、商品／订阅是否可用、是否处于基线或冷却阶段，并逐渠道显示等待合并、排队、接口受理、失败、结果待核对、跳过等状态，以及渠道关闭、联系方式、短信模板／额度／间隔和个人地址删除或停用等当前限制。查看原因不改变库存快照、不创建任务、不发送通知。诊断沿用后台订阅查看权限。会员仍可管理本人订阅、筛选和查看本人通知记录，接口不返回后台失败细节、系统任务编号或人工核对依据。

库存已经触发提醒，但合并或发送前可靠库存回落到门槛以内时，保留原通知有效期等待复核；同轮恢复后重新合并有效商品。临时缺失模板、发送接口未配置或停用、短信模板未审核及接口关联不一致，也会在原有效期内复核。订阅取消、后台主动关闭渠道、接收地址改变、库存未知或重新建立基线会停止旧提醒；成功和结果未知不自动补发。等待不会延长通知有效期，过期明确标记为已过期。

后台顶部增加“条件复核”数量和本轮异常核对编号。单商品或任务异常不影响其他目标继续处理；邮件、短信分别入 V10 队列，Webhook 使用独立发送额度及运行时限。通知重新合并后，旧投递仍保留商品清单和逐项处理结果。

### 人工核对和地址管理

结果未知的记录可由具备“登记通知人工核对”权限的管理员登记“已确认受理”“确认未受理”或“仍无法确认”，并填写核对依据。此操作保留原始未知结果，不自动重发、不改变订阅完成状态、不释放已占用的短信额度；可按核对结果筛选。新增权限不会授予已有普通角色。后台投递详情展示脱敏接口错误、业务返回码，并提供原生邮件或短信发送日志入口；接口受理仍不等于客户已收到。

管理员禁用个人 Webhook 后，仅后台“个人 Webhook”中的“恢复启用”可解除。会员不能重新启用、删除重建或调用测试接口绕过。恢复不补发旧通知。地址仅改名称保留任务；地址、类型、签名密钥、开关或群推送范围和门槛改变才取消旧任务，并按需要重建群基线。

群发预览三分钟内有效，确认时核对本批次商品、订阅客户、接收地址、实际使用的通知模板、接口、展示内容和预计条数；相关条件发生变化需重新预览。未使用的模板、模板备注和不影响本批次的订阅默认设置或调度设置不会作废预览。成功提交可通过同一请求编号安全重复确认，不重复创建通知。

永久删除商品保留订阅和通知历史，但不再占用每人有效订阅额度；临时隐藏仍保留额度。后台设置草稿在切换标签时保留，保存成功后清除未保存标记，关闭页面时提示仍未保存的修改。多个后台页面保存时校验最新配置，旧页面不能覆盖其他页面已保存的开关或额度；冲突保留当前草稿，重新读取前须明确确认放弃草稿。

### 筛选和操作日志

- **客户订阅**：按商品名称、订阅／商品编号搜索，组合客户编号、商品编号、订阅状态、渠道、提醒模式和创建日期。
- **通知记录**：按商品名称（包含历史商品名称）、事件／记录／系统任务编号、脱敏接收目标或原因搜索，组合通知类型、发送状态、渠道、通知来源、个人／商家群、客户编号、商品编号和创建日期。
- **通知记录 → 操作日志**：查询已有的插件审计记录，支持中文操作名称或编号搜索，按操作类型、管理员／客户／系统任务、管理员编号、相关客户编号和创建日期筛选。详情只展示操作编号、商品和设置项等允许字段，不展示完整地址、密钥或联系方式；沿用现有记录查看权限，不自动授予角色新权限。

筛选条件点击“查询”后生效并从第 1 页开始，翻页和刷新保留已应用的条件；“重置”清空条件。日期按记录创建时间，结束日期包含当天全天。查无结果时可以直接重置，无需离开页面。

自动通知在首件商品进入等待后保留合并窗口，按客户、渠道和接收地址合并；人工群发按本次批次合并。邮件、短信、每个个人地址和每个商家群分别处理，只包含该目标应接收的商品。较长的群消息会拆分。

同客户、同商品的提醒冷却从上次个人渠道接口受理时计算，重新订阅也保留这项限制。冷却期间达到门槛的补货会保存为“等待冷却后自动复核”，在前后台订阅状态中显示原因和复核时间。冷却结束后，即使库存没有再变化，每分钟检查也会重新确认当前库存、订阅、接收地址和渠道，再进入正常合并、发送流程，无需重新编辑商品。

等待复核不等于已经生成待发消息：正式通知的有效期从冷却结束且当前可靠库存满足门槛的重新确认时开始计算。等待期间库存跌破门槛则继续等候本轮的有效库存；确认售罄并再次补货时使用新轮次去重。退订、关闭渠道、更换地址、订阅过期会停止旧复核。商品隐藏、库存未知、重新开放商品或插件重新启用时取消旧复核并建立基线，不补发基线库存。定时任务短暂延迟不会被视为插件重新启用；恢复后保留原轮次和有效期，按当前库存复核，不重发已成功或结果未知的任务。

| 设置 | 默认值 |
| --- | --- |
| 个人渠道 | 邮件、Webhook 开启；短信关闭 |
| 每人有效订阅 | 20 个 |
| 订阅有效期 | 90 天 |
| 检查间隔／合并窗口 | 60 秒／60 秒 |
| 每分钟邮件／短信提交上限 | 20 封／10 次 |
| 同客户同商品提醒冷却 | 1 小时 |
| 同客户同商品短信间隔 | 24 小时 |
| 每人／全站每日短信额度 | 3／100 个预计计费条数 |
| 通知有效期 | 30 分钟 |
| Webhook 最大尝试次数 | 3 次，包含首次 |
| 上游同步结果有效期 | 15 分钟 |
| 初始商品／商家群 | 未配置 |

## 发送频率

后台「插件设置 → 通知规则 → 发送频率」分别设置全站补货订阅邮件、短信的提交上限，范围为每分钟 1–1000，默认邮件 20 封、短信 10 次。按连续 60 秒的滚动窗口计数，不在整分钟清零；自动补货、人工群发、下架通知及明确失败的重试共用对应渠道的限额，邮件和短信互不占用，Webhook 不受这两个设置影响。每次调用接口计一次，多商品合并通知仍为一次；长短信的预计计费条数继续由每日短信额度独立控制。

超额通知保留在插件待发队列，由后续 V10 分钟任务重新安排，实际发送前再次核对库存、订阅、渠道和模板。等待限速不消耗发送次数、重试次数或短信每日额度，也不延长原通知有效期；排队超过有效期后显示过期，可按需要增加通知有效期。上限不代表保证每分钟达到此数量，实际速度也受 V10 队列和接口耗时影响。后台待处理和诊断可查看限速等待原因，会员不可查看内部原因。

并发发送先在短事务中预占频率容量，进程重启和修改设置不会清零。明确失败、未知结果都保留本次频率占用；预占后因条件变化取消发送的容量也保守保留至窗口结束，防止异常期间密集提交。

## 商品下架通知

商品隐藏或删除后，仍有效的补货订阅会按客户所选的邮件、短信、个人 Webhook 接收下架通知；不受库存数量门槛和补货冷却限制，但仍遵守渠道开关、账户接收设置、短信间隔和每日额度。商家群不发送下架通知。一次补货提醒已完成、已退订或已过期的订阅不接收新的下架通知。

隐藏商品的上级分类同样视为下架；分类结构无法确认时不制造下架事件。会员商品状态区分在售、已下架、已删除与待确认。补货和下架短信共用同客户、同商品的短信间隔及每日额度，不因增加通知类型而放宽费用限制。

商品编辑、删除钩子与 V10 每分钟任务共同检查状态。下单、取消订单、服务删除和终止成功的系统钩子也会及时检查相关已开放商品的库存，记录分钟检查之间的售罄及归还；订单事务回滚时插件观察一并回滚，钩子不直接发送通知。系统商品列表的快捷隐藏操作没有编辑钩子，会由下一次分钟检查发现，随后按合并窗口排队。只有确认商品隐藏或删除才安排下架通知；售罄、库存未知、关闭数量库存控制均不算下架。安装或重新开放时建立状态基线，不对历史下架商品群发。

同次下架只提醒一次，重复编辑、轮询或隐藏后删除不会重复推送。重新上架后再次下架才产生新通知。多商品按客户、渠道、地址合并，补货和下架分别合并、使用独立模板。发送前恢复上架、退订、接收地址变更或渠道关闭时停止旧通知；合并中的部分商品恢复时重建剩余有效商品通知。

下架通知不完成“提醒一次”订阅、不改变补货冷却起点。订阅在原有效期内保留，恢复上架只建立库存基线，后续确认售罄再补货时仍按原规则提醒。商品删除后保留原名称和通知记录，下架通知不提供失效购买链接，也不会改变已购服务。

## V10 模板

自动登记四套原生通知动作：`cr_stock_subscribe_single`（单商品补货）、`cr_stock_subscribe_multiple`（多商品补货）、`cr_stock_subscribe_delisted_single`（单商品下架）和 `cr_stock_subscribe_delisted_multiple`（多商品下架）。邮件使用 `{参数名}`，短信使用 `@var(参数名)`。插件后台提供 V10 原生编辑和关联入口。

默认补货和下架邮件使用紧凑的表格布局、小圆角及 V10 系统设置中的 Logo，包含商品清单、通知时间及订阅管理按钮；未配置 Logo 时显示站点名称，邮件客户端屏蔽图片时保留站点名称作为替代文本。无需外部字体或样式。

邮件每个商品占一行，普通行高约 36px；长名称省略显示，补货商品可点击名称前往购买页，下架商品不提供失效购买链接。清单最多展示 10 项，超出时明确显示本次总数及未展示数量，并提供“查看本次完整清单”入口，直接展开本次通知的完整商品清单。未登录时先走 V10 登录并自动返回本次通知，仅允许本人查看。这里只限制邮件 HTML 展示，商品总数、完整纯文本清单、会员通知记录及 Webhook 不截断；库存及价格仍按后台展示开关控制。

通知合并前不依赖某一种商品数量模板，合并后按实际单商品或多商品分别校验；一种模板异常不会阻止另一种模板正常发送。配置临时异常的任务仍受原通知有效期限制。

安装或更新只补建缺失模板。仅当邮件主题与正文均与已发布的默认值完全一致时，才自动替换为新布局；商家自定义的主题、正文、接口与模板关联均保留。已自定义模板的商家可在原生邮件编辑器按需使用下列 HTML 参数。

“国内短信模板”“国际短信模板”分别打开对应接口的 V10 模板管理页，按页面所示的模板编号找到补货订阅模板后编辑。

| 参数 | 内容 |
| --- | --- |
| `stock_product_name` | 商品名称，多商品时为首件 |
| `stock_product_short_name` | 首件商品短名，最多 20 个字符，超长包含省略号；可选短信参数，不修改默认模板 |
| `stock_product_count` | 本次商品总数，不受邮件展示上限影响 |
| `stock_product_list` | 纯文本商品清单；下架通知不含失效购买地址 |
| `stock_product_list_html` | 紧凑邮件商品清单，最多 10 项，超出附剩余数量及订阅入口 |
| `stock_product_display_count` | 邮件实际展示数量，最多 10 项 |
| `stock_product_remaining_count` | 邮件未展示数量 |
| `stock_system_logo_html` | 系统 Logo 的邮件 HTML；未配置时显示站点名称 |

## Webhook

内置企业微信机器人、钉钉机器人和通用 JSON，无需其他收费插件。机器人需使用官方地址；钉钉可填写加签密钥，并按机器人要求配置关键词等接收条件。接收地址须为可解析到公网的 HTTPS 地址，使用有效证书。内网、回环、保留地址和重定向均不支持。

通用 JSON 示例：

```json
{
  "event": "stock.restocked",
  "event_id": "每次投递的唯一编号，同次重试保持不变",
  "source": "automatic",
  "restocked_at": "2026-11-01T13:00:00+08:00",
  "products": [{"product_id": 1, "name": "示例商品", "quantity": 5, "purchase_url": "https://商家域名/cart/goods.htm?id=1"}]
}
```

商品下架使用 `event=stock.delisted`、`delisted_at` 和 `manage_url`，商品项保留编号和名称，不含购买地址、库存或价格。

具体库存和当前展示价格是否出现由后台设置决定。群消息不包含客户资料。显式测试使用 `source=test` 和测试商品内容。

通用 JSON 请求头包含 `X-Stock-Event`、`X-Stock-Timestamp`。填写签名密钥后，`X-Stock-Signature` 为 `sha256=` 加上 `HMAC-SHA256(时间戳 + 换行 + 原始请求体, 密钥)` 的十六进制结果。接收方可按事件编号去重，并校验时间和签名。HTTP 2xx 表示通用接收端受理；企业微信、钉钉同时要求业务 `errcode=0`。机器人 HTTP 成功但回包为空、无法解析或业务码不明确时保留结果待核对，不自动重试。

同域名解析到多个公网 IP 时，仅在确认尚未发出请求的连接失败后尝试其他已校验 IP，最多五个地址、共用十秒解析、连接及请求预算；上传中断、超时或响应不明确时不切换地址重复发送。通知有效期至少 60 秒且须大于合并窗口；建议另外预留 180 秒供 V10 分钟任务和发送队列处理，限速排队较多时适当加长。较短有效期可以保存，后台提供提示；默认仍为 30 分钟。

## 结果、停用与数据

“等待合并”“已进入 V10 队列”“正在发送”“接口已受理”“明确失败”“结果待核对”“跳过”“过期”分别记录。**入队成功不表示客户收到；接口已受理也不保证阅读或最终送达。** 超时、响应过大或发送进程中断等结果未知的情况停止自动重发，避免重复通知和短信计费。

邮件和短信使用插件专属的 V10 通知任务，实际执行调用 V10 原生发送器、模板和日志；Webhook 使用插件投递表。合并完成和实际发送前均复核库存、退订、地址和渠道。部分商品失效时取消旧合并任务，重新合并剩余有效商品。

停用插件停止新任务，取消待发任务；重新启用先建立库存基线。已经开始的外部请求无法撤回，结果仍保留供核对。卸载取消待发任务并保留设置、订阅、模板、通知和审计历史；重新安装不重发旧通知。备份时须同时保存插件业务表与 Web 目录外的私有主密钥文件。默认文件为站点根目录下 `data/cr_stock_subscribe/master.key`，权限为 0600，由运行 PHP 的用户持有；站点根目录指 `public/` 的上一级，密钥不放在插件目录、运行缓存或安装包中。卸载会保留密钥。迁移或恢复时复制原密钥并设置正确所有者与权限，不要用新密钥替代。

批量调度按完整合并组领取提醒，处理条数上限不会截断同一客户、渠道和地址的商品清单；Webhook 仍按平台长度限制拆分。邮件、短信原生接口遇到无法确认是否受理的错误时记为“结果待核对”，不会因错误文案没有包含“超时”而自动重发；明确的认证、接收地址或业务拒绝仍执行有界重试。

首版以 PHP 7.4 为运行基线，已验证 V10 10.7.2 与 10.7.4 的原生安装和核心通知流程，适配标准会员页及 CRA1。需要系统已有的 MySQL/InnoDB、cURL、OpenSSL、mbstring，以及可用的 stream_socket_client（Webhook DNS 使用）。较新 PHP 的语法检查与 V10 整站运行兼容分开记录；其他 V10 版本需具备相同的插件、通知和任务接口，不宣称全部版本均已实测。业务文件全部在本插件目录中，验收脚本和私有资料不随安装包交付。

## 本次通知详情与后台配置总览

默认补货及下架邮件的“查看本次通知”和超过十项时的“查看本次完整清单”使用 `stock_notification_url` 参数，绑定本次通知事件编号。客户登录后自动进入“通知记录”并展开完整商品清单；其他客户不能查看。`stock_manage_url` 继续指向订阅管理页，旧自定义模板保持原样，可按需改用新参数。历史通知中的商品删除后保留原名称，后台订阅、诊断、通知及操作日志不再提供失效商品详情链接。

“插件设置 → 通知模板”展示邮件、国内短信、国际短信和个人 Webhook 的配置状态，并分别说明四套通知动作的接口与模板问题。刷新只读检查已保存配置，不修改当前草稿、不发送测试；它不代表客户联系方式可用或外部接口必然受理。短信显示今日全站预计额度占用，包括正在发送和结果未知的预留。

商家群地址列表显示该地址最近通知的处理状态和处理时间；具备通知记录权限的管理员可以从“记录”进入该地址的筛选结果。它与显式连接测试分别记录，不把测试成功当成真实通知成功。

已有 Webhook 地址在域名故障时仍可改名或停用。新建或更换停用地址可在 DNS 未就绪时保存，地址格式、HTTPS 和显式 IP 的公网校验仍执行。启用地址、替换正在使用的地址或恢复启用须通过 DNS 与公网地址校验；每次实际发送仍重新校验并固定解析地址。后台取消客户订阅需要明确确认客户、商品和待发影响，取消确认不会写入。


## 编辑冲突、待处理和历史归档

设置、个人地址、商家群地址及订阅编辑会校验打开时的版本。同一条数据在其他页面变更后，旧页面保存会被拒绝并保留草稿；请重新打开最新内容再修改。地址仅改名不会取消已安排的通知。管理员恢复个人地址前校验 DNS 和公网地址；校验失败保持停用，恢复成功也不补发旧任务。

后台“通知记录 → 待处理明细”统一展示等待合并、条件复核、冷却等待、已关联投递及已过期的逐商品提醒，可按商品、客户、渠道、地址、类型、来源、状态和日期筛选。客户与商品链接在新标签页打开；未通知原因和待处理诊断仅供后台查看。

列表标签、筛选、页码及分类折叠状态在当前浏览器会话中按登录身份保存，最长七天；刷新后恢复，不保存编辑草稿、完整联系方式、接收地址或密钥。通知邮件中的本次通知链接优先于列表恢复状态。

“通知规则”可设置短信签名预留字符，默认 10，按 UTF-16 长度估算签名与括号；实际计费以服务商为准。群发确认只核对本批实际使用的国内或国际短信模板及接口配置；未使用的短信区域、通知类型和商品数量模板变化不影响当前预览。

历史通知归档默认关闭（0 天），启用时至少保留最近 30 天。每分钟最多标记 200 条已结束的旧通知，未归档／已归档／全部均可筛选。归档保留快照、逐商品结果、尝试记录、人工核对、短信额度和去重事实，不删除数据，也不释放磁盘空间；失败、结果未知和处理中记录不会自动归档，邮件详情链接仍可访问。

Webhook 域名解析使用服务器现有 DNS 配置和随包提供的 Net_DNS2 1.5.5 库，无需额外安装或 DNS 服务；为解析预留三秒，并与 HTTP 请求共用十秒总预算。库负责 DNS 报文与 UDP／TCP 回退，插件只选择查询域名及其别名链的地址。一个地址族暂时不可用时，仍可使用另一个地址族的有效地址。解析失败不会跳过公网地址校验，也不会访问内网；实际发送重新解析、固定目标地址、验证证书且禁止重定向。


后台每次邮件、短信调度分别按对应的每分钟上限安排入队，不再另设每批 100 条限制。该值是提交频率上限，实际吞吐仍取决于 V10 队列与发送接口。准备和实际发送前的查询缓存按阶段独立，最终复核不会复用准备阶段的旧联系方式或模板。

网络错误、超时、权限、接口不存在、请求频繁和响应格式异常会显示对应操作提示；内部数据库或程序异常详情仍只保留在服务器日志。

## 0.1.0 升级与密钥备份

0.1.1 修复旧版主密钥与 Webhook 密文存于同一个数据库的问题。正常升级会在 Web 目录外生成新的随机主密钥，在事务中重新加密已有 URL 与签名密钥，全部成功后删除数据库旧主密钥。订阅、通知关联、自定义模板与商家配置保留。遇到损坏数据时停止并回滚，不会丢弃旧配置；密钥文件丢失或损坏时也不会静默重置。

通常不需要手工配置。自定义部署可通过 PHP 环境变量 `CR_STOCK_SUBSCRIBE_KEY_FILE` 指定非公开目录中的绝对路径；Web 与定时任务须指向同一文件，多台应用服务器须使用同一私有密钥文件并支持文件锁。不可将密钥放到 Web 目录。升级前确认 PHP 对私有目录具有写权限，升级后将密钥纳入单独备份。保护对象是仅数据库泄露的场景；已含旧主密钥的历史数据库备份仍须妥善保管。
