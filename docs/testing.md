# 开发检查与测试说明

测试脚本是开发和发布时运行的辅助程序，用来验证插件行为；插件正常运行不依赖这些脚本，商城 ZIP 只包含运行目录。

## 不需要 V10 的检查

需要 Python 3、PHP CLI 和 Node.js，在仓库根目录执行：

```bash
python3 scripts/check.py
php tests/security_test.php
php tests/mail_render_test.php
python3 tests/package_test.py
python3 scripts/package.py --output /path/to/output
python3 scripts/package.py --verify /path/to/output/CrStockSubscribe-0.1.3.zip
```

非默认路径的运行时可通过 `PHP_BINARY`、`NODE_BINARY` 指定。`SOURCE_DATE_EPOCH` 可以固定 ZIP 时间戳，便于重建相同输入的包。已有安装包不会被自动覆盖。

- `check.py`：PHP／JavaScript 语法、运行文件范围、默认短信无链接、第三方许可及源码隐私检查。
- `security_test.php`：库外密钥、加解密与篡改拒绝、缺失密钥、日志脱敏、Webhook 地址检查；不读取站点配置，不需要数据库。
- `mail_render_test.php`：邮件主题使用原始文本、正文转义商品名、保留生成的 HTML 和链接、变量只替换一次；不发送真实邮件。
- `package.py`：从插件运行目录创建 `cr_stock_subscribe/` 顶层 ZIP，生成 SHA256，并核对归档内容与源码一致。
- `package_test.py`：检查错误目录层级、缺失文件、源码变化、夹带私有文件及路径越界的包会被拒绝。
- GitHub Actions：在 PHP 7.4、8.1、8.2、8.3 上执行上述检查。这些检查不代表 V10 整站已在全部 PHP 版本运行验收。

## 外部 V10 集成验收

库存、队列、权限、原生模板和页面流程需要合法可用的 V10 环境。V10 系统源码和数据库不随本仓库提供。

首发验收使用独立表前缀和合成账户，覆盖库存 `0→1→5`、不同门槛、售罄再次补货、下架、多商品合并、个人与群地址、人工群发、失败／未知结果、发送前条件变化、并发去重和短信限额。最终 ZIP 另外通过 V10 实际解压器和插件安装入口验证。

维护使用的完整集成脚本还需连接 V10 环境；其中的站点适配、认证材料、数据库与原始实站输出不在公共仓库公开。公开仓库提供不需要凭据的源码与安装包检查，安装后的功能验证可按下列流程完成：

1. 使用专用测试商品、本人测试账户及模拟邮件／短信／Webhook 接收端。
2. 安装后确认菜单、独立权限、四套通知动作和默认模板。
3. 商品库存为 0 时开放并订阅，依次改为 1 和 4；默认门槛 3 时应只在 4 触发。
4. 等待原有分钟任务和发送队列，不调用手动 Worker；检查通知及原生接口日志。
5. 用两个商品检查合并，用商品隐藏检查下架通知；测试退订、渠道关闭、地址变化和库存回落。
6. 检查商家群和普通会员两个角色，确认会员无法读取后台诊断或其他客户资料。
7. 检查停用、重新启用和卸载重装，保留配置及历史，不重发旧通知。

发送接口受理不等同于最终收到。短信接口和模板审核由使用者配置；Webhook 测试必须使用实际可接收请求的端点。

## 0.1.1 安全回归

两版 V10 集成环境分别验证了新安装不写入数据库主密钥、从真实 0.1.0 配置迁移、迁移失败回滚及重试、恢复密钥、保留自定义模板，以及升级前的 Webhook 任务继续发送且不重复。每版同时执行库存、合并、限速和并发等 175 项业务回归。公共安全脚本另有 42 项独立检查。

全新数据库安装使用原版 V10 安装器和默认主题，另以浏览器检查后台插件安装、启用及设置；不把隔离表测试当作全新系统安装。验证使用合成账户与测试地址，私有环境及浏览器认证状态不进入仓库或安装包。

## 0.1.2 问题回归

V10 10.7.2 和 10.7.4 各执行 188 项业务检查，新增检查覆盖新旧商品混选保存、订阅版本冲突及整批回滚、父子分类及隐藏继承，以及订阅修改后旧合并投递的取消、重建、历史明细和去重。

两个系统版本均从真实 0.1.0、0.1.1 源码安装后，通过 V10 原生升级流程验证到 0.1.2，保留配置、自定义模板和待发通知。最终 ZIP 另外验证原生解压、安装、队列发送及启停重装。

浏览器按管理员与普通会员检查全部插件标签页、批量操作、记录、个人及商家 Webhook、权限、桌面与手机布局，并针对混选保存、父分类筛选、多页面冲突及原生登录回跳补做实际点击检查。通知接收使用模拟端，不向真实客户或商家群发送测试消息。

## 0.1.3 问题回归

V10 10.7.2 和 10.7.4 各执行 228 项业务检查，新增覆盖代理商品直接更新系统库存、库存回滚开关、旧同步时间戳、群地址保留历史关联后改名和停用、队列统计与联合索引迁移。原生 AppInit 和插件停启使用独立进程验证，确认已有监听会取消旧任务并重建基线。

两个系统版本分别验证从真实 0.1.0、0.1.1、0.1.2 经原生流程升级，保留配置、自定义模板、历史和待发通知。最终 ZIP 验证原生解压、安装、队列发送及启停重装。邮件另用两个版本的原生发送逻辑检查主题文本、正文转义、四种默认模板、自定义模板及发送钩子。

浏览器覆盖管理员、普通会员、标准主题与 CRA1 的主要操作，并定向检查商品本地搜索、群地址停用、通知详情返回普通列表和发送频率估算。会员手机页面保持页面内布局；后台壳在手机上的桌面最小宽度遵循系统限制。排空时间与过期提示是估算，未将模拟发送受理描述为实际客户送达。
